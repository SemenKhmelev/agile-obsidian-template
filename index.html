Шаблон Obsidian для командных спринтов

Спринт — это папка с файлами

Команда ведёт спринты в своём git-репозитории. Доска, учёт времени, отчёты и роадмап хранятся в markdown-файлах. Для работы не нужны сервер, API или стороннее облако.

159 спринтов в команде из 12 человек · MIT · всё содержимое в обычном тексте

01 / DATA

Данные в вашем репозитории

В трекере остаются решения команды, затраченное время и причины изменений. В agile-obsidian эти записи хранятся в файлах, вместе с историей изменений в git.

Записи пережили смену инструмента

Наше расширение для учёта времени перестало работать с устареванием браузерной технологии. Сам проект сменил владельца. Записи сохранились в файлах.

У каждого есть локальная копия

Полная копия репозитория лежит на диске у каждого участника команды. Доступ к этим файлам не зависит от тарифа сервиса или статуса аккаунта.

Открывайте в привычном редакторе

Markdown с YAML-заголовком можно редактировать в Obsidian, VS Code или vim. Те же файлы доступны для поиска через grep, скриптов на Python и AI-агентов.

02 / MARKDOWN

Одна строка — три представления

Добавьте строку в запись за день. Доска и отчёт прочитают её из того же файла и покажут потраченное время по задаче.

* [cardref:: [[sprint2/tasks/Ошибка на открытии bpmn-фрейма|Ошибка на открытии bpmn-фрейма]]]
  [action:: fix] [spent:: 5]
  Удалось повторить ошибку.

В строке записи за день указываются ссылка на задачу, тип деятельности и часы.

Та же задача на доске. Дробь «потрачено / оценка» стоит на карточке, при перерасходе она краснеет — как у соседней задачи в review.

Отчёт спринта собирает оценку, факт и точность из записей.

03 / AI AGENTS

Как AI-агент работает с задачами

AI-агент читает задачи и записи о времени прямо из репозитория. Правки вносит в те же markdown-файлы, с которыми работает команда.

× API

Доступ к сервису через API

  • Зарегистрировать OAuth-приложение и хранить его секрет
  • Разобраться в схеме данных и версиях API
  • Учитывать лимиты запросов при выборке данных
  • Настроить MCP-сервер или написать код для обращения к API
  • Собирать контекст проекта из ответов на запросы
  • Проверять изменения агента в интерфейсе сервиса

✓ FILES

Папка с файлами

  • Перейти в каталог репозитория через cd
  • Искать записи по всем спринтам через grep
  • Редактировать строки в файле задачи
  • Передать историю задачи по спринтам в контекст модели
  • Проверять правки агента через git diff
  • Отменять коммиты агента командой git revert

Поиск по записям

Команда grep -r "action:: dev" sprint2/comments находит записи о разработке в спринте.

Запись времени

Агент добавляет [spent:: 2] в строку записи за день. Формат тот же, что при ручном вводе.

История задачи

Поле previous связывает копии задачи в разных спринтах. По этим ссылкам можно собрать её историю для модели.

Проверка изменений

В git diff видны изменённые строки. Если правки уже закоммичены, отменить коммит можно через git revert.

04 / WORKFLOW

Цикл спринта

Каждые две недели команда проходит шесть шагов. Скрипт готовит новый спринт, участники ведут задачи и записи о времени, а отчёты собирают данные к ретро.

01

Создайте новый спринт

Скрипт create_new_sprint.py копирует структуру прошлого спринта, убирает завершённое, переносит хвосты, проставляет ссылки на предыдущие версии задач и переключает настройки плагинов на новый каталог.

02

Задачи и доска спринта

В файле задачи указаны оценка, чеклист этапов и ссылка на прошлый спринт. Kanban-плагин редактирует доску в файле board.md. Он хранится в git, поэтому расположение колонок общее для команды.

03

Учёт времени за день

Создайте файл дня кнопкой на панели. Горячая клавиша добавит строку для задачи, типа деятельности и часов. Ввод с клавиатуры занимает меньше минуты за день.

04

Работа участников

Аватарки слева фильтруют доску по человеку, правый клик открывает сквозную ленту его записей за все спринты. На карточке — дробь «потрачено / оценка», красная при перерасходе.

05

Отчёты для ретро

Отчёты показывают точность оценок, распределение часов по типам деятельности, перегрузки по дням и сопутствующую деятельность рядом с двумя прошлыми спринтами.

06

Обмен изменениями

В палитре команд закреплены Git: Pull и Git: Commit-and-sync: первая забирает правки команды, вторая отправляет ваши. Автоматический бэкап выключен, изменения уходят на сервер по вашей команде.

Каждый ведёт свой файл дня, поэтому конфликты при слиянии редки.

05 / FEATURES

Что внутри

В шаблон включены плагины и скрипты. Два демо-спринта вымышленной команды показывают, как устроена работа.

+

Учёт времени по типам деятельности

Тип деятельности задаётся в строке: разработка, дизайн, ритуалы или поддержка

+

Дробь «потрачено / оценка»

На карточке, в ленте и в отчётах, с подсветкой перерасхода

+

Сквозная история задачи

Копии задачи связаны между спринтами; потраченное время суммируется

+

Временной долг

Недоработанные часы фиксируются и закрываются отработкой

+

Отчёты спринта

Точность оценок, часы по людям и дням, графики по типам деятельности

+

Roadmap

Видения, темы и эпики, связанные со спринтовыми задачами

+

Диаграмма Ганта

Сроки меняются перетаскиванием полос прямо на диаграмме

+

Фильтр по аватаркам и лента участника

Доска фильтруется кликом, лента открывается правым кликом

06 / LIMITS

Ограничения

При выборе шаблона стоит учесть несколько ограничений.

  • —

    Уведомления и упоминания не поддерживаются.

  • —

    Доступ к репозиторию открывает весь спринт. Настроить права точнее нельзя.

  • —

    Бэклог ограничен текущим спринтом. Дальнейшее планирование ведётся отдельно.

  • —

    На доске возможны мердж-конфликты. Частый обмен изменениями снижает их вероятность.

  • —

    Шаблон рассчитан на небольшую команду. Для двухсот человек нужен корпоративный трекер.

07 / START

Попробовать

Открыть первую доску можно за пять минут, включая установку Obsidian.

git clone https://github.com/SemenKhmelev/agile-obsidian-template.git

  1. Установить Obsidian

    Бесплатно, на всех платформах.

  2. Клонировать репозиторий

    Выполните команду выше, чтобы скачать шаблон.

  3. Открыть папку как хранилище

    При открытии Obsidian попросит подтвердить доверие автору хранилища. Подтвердите, чтобы использовать включённые в шаблон плагины и настройки.

  4. Посмотреть демо и добавить свои данные

    В шаблоне два демо-спринта с вымышленной командой. Как перейти на свою — в CONTRIBUTING.
