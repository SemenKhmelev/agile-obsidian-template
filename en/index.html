An Obsidian template for team sprints

A sprint is a folder of files

An Obsidian vault put together for sprint-based development: configured plugins, our own scripts and templates, a process that works. Board, time tracking, reports and roadmap live as markdown files in your own git repository.

Get the template See how it works

Used by a team of 12 across 159 sprints · MIT · all content in plain text

01 / STACK

What you actually get

Clone the repository, open it in Obsidian, and everything a team needs for sprint work is already there: configured plugins, our scripts and templates, a demo example and the process itself.

Obsidian as the workplace

Local markdown files, instant search across every sprint, keyboard shortcuts, link previews and a command palette. The editor is free and runs on every platform.

Plugins, already configured

Kanban, Dataview, Templater, Charts, QuickAdd and Obsidian Git ship inside the repository together with their settings. Nothing to set up after cloning.

Our scripts, views and templates

The avatar rail and member feed on the board, spent-to-estimate fractions, sprint reports, a roadmap with a Gantt chart, templates for the daily note, a task and a time debt, and a script that creates the next sprint.

A working process

A sprint routine close to Scrum: planning, daily time logging, the board, a retrospective driven by reports. It was worn in by a real team rather than invented for a showcase.

02 / DATA

Data in your repository

A tracker holds team decisions, time spent and the reasons behind changes. In agile-obsidian, those records live in files with their revision history in git.

Records that outlasted the tool

Our time tracking extension stopped working when its browser technology became obsolete. The project also changed owners. The records remained intact as files.

A local copy for every teammate

Each teammate has a complete copy of the repository on disk. Access to those files does not depend on a service plan or account status.

Use your usual editor

Edit markdown with YAML headers in Obsidian, VS Code or vim. The same files can be searched with grep and read by Python scripts or AI agents.

03 / MARKDOWN

One line, three views

Add a line to your daily note. The board and report read it from the same file and display the time spent on the task.

* [cardref:: [[sprint2/tasks/Ошибка на открытии bpmn-фрейма|Ошибка на открытии bpmn-фрейма]]]
  [action:: fix] [spent:: 5]
  Удалось повторить ошибку.

Each daily note entry includes a task link, an activity type and hours spent.

The same task on the board. The spent-to-estimate fraction sits on the card and turns red when the estimate is passed, as on the neighbouring card in review.

The sprint report gathers estimates, actuals and accuracy from the entries.

An AI agent reads tasks and time entries directly from the repository. It edits the same markdown files the team uses.

✓ FILES

A folder of files

  • Open the repository directory with cd
  • Search entries across sprints with grep
  • Edit lines in the task file
  • Pass task history across sprints to the model as context
  • Review agent changes with git diff
  • Undo agent commits with git revert

Search entries

The command grep -r "action:: dev" sprint2/comments finds development entries in the sprint.

Log time

The agent adds [spent:: 2] to a daily note entry, using the same format as a manual entry.

Task history

The previous field links copies of a task across sprints. These links let you gather its history for the model.

Review changes

Changed lines appear in git diff. Once edits are committed, you can undo the commit with git revert.

05 / WORKFLOW

The sprint cycle

The team follows six steps every two weeks. A script prepares the new sprint, members update tasks and log time, and reports gather the data for the retrospective.

01

Create a new sprint

The create_new_sprint.py script copies the previous sprint structure, removes completed work, carries over unfinished tasks, links them to previous versions and points plugin settings to the new folder.

02

Sprint tasks and board

Each task file contains an estimate, a checklist of stages and a link to the previous sprint. The Kanban plugin edits the board in board.md. Git stores the file, so the team shares the same column layout.

03

Daily time entries

Create a daily note with the toolbar button. A hotkey adds a line for the task, activity type and hours. Logging a day from the keyboard takes under a minute.

04

Work by team member

Avatars on the left filter the board by person; a right click opens their feed of entries across every sprint. Each card shows a spent-to-estimate fraction, turning red when over budget.

05

Reports for the retrospective

Reports show estimate accuracy, hours by activity type, overloaded days and supporting work, alongside data from the two previous sprints.

06

Sharing changes

The command palette has Git: Pull and Git: Commit-and-sync pinned: the first brings in what the team changed, the second sends yours. Automatic backup is off, so changes leave your machine when you say so.

Syncing is a single Obsidian Git command. Conflicts are rare: everyone writes into their own daily file.

07 / LIMITS

Limitations

A few limitations to consider when choosing the template.

  • —

    Notifications and mentions are not supported.

  • —

    Repository access covers the entire sprint. More granular permissions are not available.

  • —

    The backlog covers the current sprint. Longer-term planning happens elsewhere.

  • —

    Board edits can cause merge conflicts. Frequent syncing makes them less likely.

  • —

    The template is built for a small team. Two hundred people need a corporate tracker.

08 / START

Try it

Open your first board in five minutes, including the Obsidian installation.

git clone https://github.com/SemenKhmelev/agile-obsidian-template.git

  1. Install Obsidian

    Free, on every platform.

  2. Clone the repository

    Run the command above to download the template.

  3. Open the folder as a vault

    When you open the vault, Obsidian asks you to trust its author. Confirm to use the plugins and settings included in the template.

  4. Explore the demo and add your data

    The template ships with two demo sprints run by a fictional team. Switching to your own is described in CONTRIBUTING.
