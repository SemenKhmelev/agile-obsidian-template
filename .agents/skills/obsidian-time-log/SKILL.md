# Списание времени

Один день — один файл `sprintN/comments/ГГГГ-ММ-ДД-Имя Фамилия.md`. Внутри — записи
с inline-полями `[cardref::]`, `[action::]`, `[spent::]`. Раскладка vault описана
в [README](../../../README.md), правила заполнения записей — в [AGENTS.md](../../../AGENTS.md).

## Порядок

1. **Определить дату.** Не верь `date` не глядя: если машина уходила в сон, часы
   возвращаются со старым временем. Сверь с датами последних коммитов vault и с тем,
   за какие дни уже есть файлы у коллег. После полуночи «сегодня» у пользователя —
   предыдущий календарный день.
2. **Найти спринт**: поля `start`/`end` в `sprintN/readme.md` покрывают дату. Спринта
   нет — время заносить некуда: новый спринт заводит ведущий командой
   `python3 -B _scripts/create_new_sprint.py`, а не агент.
3. **Обновить vault**: `git pull --rebase --autostash`.
4. **Собрать состав дня по фактам**, а не по памяти (источники — ниже).
5. **Написать файл** по образцу соседнего дня того же спринта; шаблон одной записи —
   `_templates/time-spent-comment-template.md`.
6. **Свести сумму** и показать пользователю таблицу «карточка / action / часы», явно
   пометив часы, которые проставил сам. Он поправит одной репликой.
7. **Закоммитить**; `push` — только по явной команде.

## Откуда брать состав дня

- **Продиктованное самим человеком** — главный источник, остальное лишь уточняет часы.
- **git**: коммиты и `reflog` рабочих репозиториев. Смотри **author date**, а не commit
  date: rebase переписывает вторую, и после ребейза старые коммиты выглядят сегодняшними.
- **Журналы сессий AI-агента**, если работа шла с ним: хронология просьб за день
  восстанавливает, чем человек занимался. Служебные блоки отбрасывай.
- **Записи коллег за тот же день**: сколько поставили на ритуалы, был ли общий сбой или
  общее мероприятие.

## Правила записи

- `cardref` ведёт на **реальную задачу**, если работа была по задаче. Ищи задачу по
  исполнителю и теме:

  ```bash
  grep -l "user: Имя Фамилия" sprintN/tasks/*.md
  ```

  Ревью списывается на задачу автора правок. Предопределённые карточки из
  `sprintN/tasks/_predefined/` — только для того, у чего задачи нет: планирование и
  митинги, найм, поддержка, документация, сопутствующая деятельность, анализы,
  потрачено, другое.
- Проверяй, что файлы задач существуют, до коммита:

  ```bash
  grep -o "\[\[sprintN/tasks/[^]|]*" файл.md | sed 's/\[\[//' \
    | while read -r p; do [ -f "$p.md" ] && echo "OK $p" || echo "НЕТ $p"; done
  ```

- `action` — из списка в `_templates/time-spent-comment-template.md`: `other`, `review`,
  `feat`, `fix`, `refactor`, `docs`, `sd`, `agile`, `analysis`, `test`, `design`, `devops`.
  Ритуалы спринта — `agile`, сопутствующая деятельность — `sd`, разборы трудоёмкости —
  `analysis`.
- Текст записи — от первого лица, суть работы и результат. Имена восстанавливай по vault:
  фамилию из диктовки ищи среди авторов записей и в прошлых списаниях.
- Сумма за день:

  ```bash
  grep -o "\[spent:: *[0-9.]*\]" файл.md | grep -o "[0-9.]*" | awk '{s+=$1} END {print s}'
  ```

## Правка уже занесённого дня

Пока коммит не запушен — `git commit --fixup <хеш>` и
`GIT_SEQUENCE_EDITOR=true git rebase --autosquash origin/main`: история остаётся одним
коммитом на день. После пуша — обычный коммит поверх.

## Грабли

| Симптом | Что на самом деле |
|---|---|
| Дата в `date` расходится с датами коммитов в vault | Часы машины отстали после сна и синхронизируются позже. Дату дня бери от коммитов и файлов коллег |
| `bc: command not found` | Не везде установлен, суммируй `awk` |
| `pull --rebase` падает на «Please move or remove them» | Твой untracked-файл конфликтует с входящим. Сначала закоммить своё, потом повторяй pull |
| Конфликт add/add по файлу дня | На сервере пустая заготовка, созданная кнопкой Obsidian, локально — заполненный день. Бери свою версию: `git show :3: > файл`, `git add`, `GIT_EDITOR=true git rebase --continue` |
| Ревью списано на предопределённую карточку | Она взята по аналогии с чужим списанием. Ревью идёт на задачу автора правок |
| В дереве есть файлы, которые git считает удалёнными | Имя заметки длиннее лимита файловой системы. Не делай `git add -A` и `commit -a` вслепую, иначе зафиксируешь удаление чужих заметок |
